# TripPlanner

지도와 타임라인을 함께 사용하여 여행의 장소, 일정, 이동 계획을 구성하고 관리할 수 있는 웹 기반 여행 계획 서비스입니다.

장소를 먼저 수집한 뒤 실제 일정에 배치하는 방식으로 계획할 수 있으며, Google Maps와 NAVER Maps를 이용한 장소 검색, 지도 표시 및 경로 조회를 지원합니다.

---

## 소개

TripPlanner는 여행 계획을 단순한 장소 목록이 아닌 **시간과 위치를 함께 고려하는 일정**으로 구성하기 위해 개발한 웹 애플리케이션입니다.

방문하고 싶은 장소를 먼저 수집하고, 이를 타임라인에 배치하여 실제 여행 일정을 구성할 수 있습니다. 일정 사이의 이동 계획, 숙소와 같은 반복 거점, 주변의 대안 일정(PLAN B)도 하나의 여행 안에서 함께 관리할 수 있습니다.

여러 사용자가 동일한 서버에서 각자의 계정을 이용할 수 있으며, 여행별 접근 권한을 지정하여 가족이나 지인과 계획을 공유할 수 있습니다.

주요 목표:

* 지도와 타임라인을 결합한 여행 일정 관리
* 후보 장소 수집과 실제 일정 배치의 분리
* 일정 변경을 고려한 PLAN B 및 거점 관리
* Google Maps / NAVER Maps를 이용한 장소 및 경로 정보 연동
* 여행별 저장 및 사용자 접근 권한 관리
* 개인 서버에서 직접 운영할 수 있는 Self-hosted 구조

## 주요 특징

### Timeline 기반 일정 구성

* 날짜와 시간을 기준으로 여행 일정을 배치
* 일정 이동 및 시간 조정을 위한 Drag & Drop 지원
* 일정 시작/종료 시간 및 체류시간 설정
* 일정 겹침, 고정 일정 충돌, 이용 가능 시간 등의 배치 상태 표시
* 날짜별 색상 및 일정별 사용자 지정 색상 지원
* Undo / Redo 지원

### 장소 및 일정 후보 관리

* 아직 시간에 배치하지 않은 장소와 일정을 별도로 보관
* 후보 일정을 Timeline으로 Drag & Drop하여 배치
* Timeline의 일정을 다시 후보 목록으로 이동 가능
* 일정 정보와 장소 정보를 분리하여 동일한 장소를 여러 일정에서 활용

### PLAN B

예정된 장소를 방문하지 못했을 때 사용할 주변 대안 일정을 별도로 관리할 수 있습니다.

PLAN B는 독립된 여행 계획이 아니라 기존 일정 주변의 후보 장소를 보관하는 용도로 사용하며, 필요할 경우 일반 일정과 동일하게 Timeline에 배치할 수 있습니다.

### 거점 (Base)

숙소, 터미널 등 여행 중 반복해서 사용하는 장소를 거점으로 등록할 수 있습니다.

거점 원본은 유지되며 필요한 날짜와 시간에 반복해서 Timeline에 배치할 수 있습니다.

### 주요 이동

일반적인 장소 간 연결과 별도로 다음과 같이 출발 및 도착 시간이 명확한 이동 일정을 관리할 수 있습니다.

* 열차
* 항공
* 선박
* 버스
* 자동차 / 기타

편명, 열차번호, 좌석, 출발지, 도착지와 메모 등을 일정과 함께 관리할 수 있습니다.

### 지도 연동

* Google Maps / NAVER Maps Provider 지원
* 장소명 및 주소 검색
* 지도상의 장소를 일정 후보 또는 PLAN B로 추가
* 자동차 및 지원되는 이동수단의 경로 조회
* 경유지 설정
* 일정 및 이동 경로 지도 표시
* 저장된 장소 위치의 수동 갱신

### 보기 모드

편집 UI를 제외하고 여행 일정을 확인하기 위한 별도의 보기 모드를 제공합니다.

* 날짜별 일정 확인
* 주요 이동 표시
* 예상 비용 및 준비물 정리
* 일정별 상세 메모 확인
* 전체 페이지 / 스크롤 캡처를 고려한 레이아웃

## 실행 방법

### 1. 저장소 복제

```bash
git clone <repository-url>
cd TripPlanner
```

### 2. 패키지 설치

```bash
npm ci
```

### 3. 환경 설정

저장소의 `.env.example`을 참고하여 로컬 환경 설정 파일을 생성합니다.

```bash
cp .env.example .env.local
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env.local
```

`.env.local`에 서버 실행 및 지도 Provider에 필요한 값을 설정합니다.

실제 API Key 및 관리자 인증 정보가 포함된 `.env.local` 파일은 Git 저장소에 포함하지 않습니다.

### 4. 개발 환경 실행

```bash
npm run dev
```

개발 서버가 시작되면 터미널에 표시된 주소를 웹 브라우저에서 엽니다.

### 5. Production Build

```bash
npm run build
```

빌드 결과는 `dist/` 디렉터리에 생성됩니다.

## 사용 방법

### 1. 여행 생성

로그인 후 여행 목록에서 새 여행을 생성합니다.

각 여행은 독립적으로 저장되며 서버 설정에 따라 다른 사용자와 접근 권한을 공유할 수 있습니다.

### 2. 장소 및 일정 추가

**일정 추가**에서 기존 장소를 선택하거나 새로운 장소를 검색합니다.

등록한 일정은 바로 Timeline에 배치하거나 여행 보관함에 일정 후보로 보관할 수 있습니다.

### 3. Timeline 배치

여행 보관함의 일정을 원하는 날짜와 시간으로 Drag & Drop하여 배치합니다.

배치된 일정은 Timeline에서 이동하거나 시작 및 종료 시간을 조정할 수 있습니다.

### 4. 이동 계획

서로 인접한 일정 사이에 이동 계획을 설정할 수 있습니다.

지도 Provider가 지원하는 이동수단은 실제 경로를 조회할 수 있으며, 직접 이동 방법과 예상 소요시간을 입력하는 것도 가능합니다.

열차나 항공편처럼 출발 및 도착 시간이 일정 자체의 일부인 경우 **주요 이동**으로 등록합니다.

### 5. PLAN B 및 거점

일정 주변의 대안 장소는 PLAN B에 보관할 수 있습니다.

숙소와 같이 반복적으로 방문하는 장소는 거점으로 등록한 뒤 필요한 시간에 여러 번 배치할 수 있습니다.

### 6. 저장 및 보기

편집한 여행은 상단의 저장 버튼을 통해 서버에 저장합니다.

보기 모드에서는 편집 요소를 제외하고 날짜별 일정, 이동 계획, 예상 비용, 준비물 및 상세 정보를 확인할 수 있습니다.

## 프로젝트 구조

```text
TripPlanner/
├── config/                  # 지도 및 Provider 관련 설정
├── public/                  # 정적 리소스, 아이콘 및 폰트
├── scripts/                 # 개발 실행 스크립트
├── server/                  # Node.js 서버 및 SQLite persistence
├── src/                     # React / TypeScript Frontend
│   ├── i18n/                # UI 문자열 및 locale
│   ├── map/                 # 지도 및 Provider abstraction
│   ├── persistence/         # Snapshot 및 저장 관련 로직
│   ├── providerData/        # 외부 Provider 데이터 처리
│   └── transit/             # 경로 및 대중교통 데이터 처리
├── tests/                   # 회귀 및 Release 테스트
├── .env.example             # 환경변수 예제
├── package.json
├── package-lock.json
└── vite.config.ts
```

### Frontend

`src/`에는 Timeline, 지도, 일정 편집, 여행 보관함, PLAN B, 거점 및 관리 화면을 포함한 클라이언트 애플리케이션이 위치합니다.

사용자에게 표시되는 한국어 UI 문자열은 `src/i18n/locales/ko-KR.ts`에서 관리합니다.

### Server

`server/`는 다음 기능을 담당합니다.

* 사용자 인증
* 여행 데이터 저장
* 여행별 접근 권한 관리
* SQLite 데이터베이스
* 첨부 이미지 관리
* Provider 캐시 및 정책 관리
* 저장 데이터 검증

### Runtime Data

실행 중 생성되는 데이터는 소스 코드와 분리하여 관리합니다.

대표적으로 다음 데이터는 Git 저장소에 포함하지 않습니다.

```text
.env.local
.tripplanner/
*.sqlite
*.sqlite-shm
*.sqlite-wal
node_modules/
dist/
```

## 지도 및 외부 서비스

TripPlanner는 지도 기능을 Provider abstraction을 통해 분리하여 관리합니다.

현재 다음 Provider를 지원합니다.

### Google Maps

주요 용도:

* 지도 표시
* 장소 검색
* 장소 위치 확인
* 지원되는 이동수단의 경로 조회

### NAVER Maps

주요 용도:

* 국내 지도 표시
* 장소 및 위치 정보 연동
* 자동차 경로 조회

사용 가능한 기능은 각 지도 Provider의 API 지원 범위 및 설정에 따라 달라질 수 있습니다.

### API 요청

일부 지도 API는 요청량에 따라 비용 또는 사용량 제한이 발생할 수 있습니다.

TripPlanner는 불필요한 자동 요청을 줄이기 위해 장소 검색 및 경로 조회 등 외부 API를 사용하는 주요 작업을 명시적인 사용자 동작을 중심으로 수행하도록 설계했습니다.

API Key, 허용 도메인, API 제한 및 사용량 제한은 실제 배포 환경에 맞게 별도로 설정해야 합니다.

## 데이터 및 보안

### 사용자 인증

TripPlanner 서버는 사용자 계정과 관리자 계정을 구분하여 관리합니다.

일반 사용자의 계정은 관리자 승인 후 활성화할 수 있으며, 여행별로 전체 사용자 또는 지정 사용자에게 접근 권한을 부여할 수 있습니다.

### 비밀번호

사용자 비밀번호는 원문으로 저장하지 않습니다.

관리자 인증 정보와 배포 환경별 설정값은 소스 코드와 분리된 환경 설정을 사용합니다.

### 여행 데이터

여행 데이터에는 다음과 같은 정보가 포함될 수 있습니다.

* 장소
* 일정
* 이동 계획
* PLAN B
* 거점
* 예상 비용
* 준비물
* 메모
* 첨부 이미지

실제 실행 중 생성되는 데이터베이스와 첨부 파일은 `.tripplanner/`에 저장되며 Git 저장소에서 제외됩니다.

### Provider Data

외부 지도 Provider에서 얻은 데이터는 각 서비스의 이용약관 및 저장 정책을 고려하여 처리해야 합니다.

`config/`에는 Provider 데이터의 사용 및 보존 정책을 관리하기 위한 설정이 포함되어 있습니다.
